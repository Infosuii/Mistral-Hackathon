# GAMBIT handoff prompt for a fresh agent

## Your assignment

Continue the map and transport redesign in **GAMBIT**, the voice-driven strategy game in **Infosuii/Mistral-Hackathon**. The working branch is **om/map-decision-animations**. Start there. Its latest game change at this handoff is **7cff885**. The previous validated atlas cut was **c557642**. Use Git history and the implementation below as your source of truth. Compare the branch against current upstream before coordinating integration. Team planning and requests live in GitHub issues #25–#28. The team may have continued working since this prompt was written.

The player controls Valdoria by default, shares the map with Kessaria, Nordhaven, Ostrava and Zarnia, and can negotiate by voice or text. Strategy advances by month. One Berth and Grey Fever use a separate crisis clock. Your focus is the **ordinary top-down campaign map** and how its infrastructure supports gameplay.

## Read the user’s latest direction first

The latest correction supersedes the earlier city-detail prototype. The user attached an overhead city-builder screenshot showing curved suburban streets, dense downtown buildings, a large motorway interchange, tree cover, neighbourhood services, and bridges crossing a wide waterway. Earlier references included a strategy atlas with muted national colours, geographic coastlines and named cities, and a top-down pixel city with streets and freight yards. Use those references for density, hierarchy, and legibility. Draw original assets and layouts for GAMBIT.

- City buildings and transport belong directly on the ordinary campaign map and must read at the starting camera scale. The user repeatedly rejected empty nations and specifically asked to remove the separate zoom-in city scene. The globe was already removed. Keep ordinary campaign pan, zoom and Fit map as navigation. A city click should select its nation and show station information while leaving the camera where it is.
- Keep large, coherent countries and natural coastlines. The current authored atlas measures about **60% land and 40% water**. It has a large mainland, a northern island, smaller islands, rivers and lakes. Preserve the 40 province IDs and the five starting nations’ contiguous territories. Existing saves, county production, crisis landmarks and port positions depend on that geography.
- Present cities as a continuous part of the terrain. Use visible suburbs, town centres, parks, industrial buildings, government or service buildings, stations, runways and airport terminals. The user wants a city-builder level of visual detail from overhead. Buildings should follow local streets and terrain instead of looking like unrelated map icons.
- Build a connected hierarchy of local streets, arterial roads, motorways, approaches, interchanges, bridges, and station or airport access. Show multiple kinds of traffic and make their movement useful and explainable. A bridge should span its water crossing. A rail line or road should route around a lake unless an authored crossing supports it.
- Design around biomes. Floodplains should constrain buildings and concentrate crossings. Forests and highlands should shape routing and travel pace. Farmland should remain readable. Airport placement, access and layouts should suit their terrain. Make differences visible beyond a label or a polygon tint.
- Keep military art grounded in the engine. Tanks on confirmed captures and fleets on actual orders already exist. Aircraft around airfields are local visual patrols. Any future tactical air or naval action should have an explicit engine outcome to drive the animation. The user deferred spies. The user wants News available and continues to care about the Red Phone and rate limits.

## How to start locally

1. Fetch the branch and check status before editing. Inspect `README.md`, `web/DESIGN.md`, this handoff and the recent commits. Read the repo’s current instructions and board if you plan to integrate with the team.
2. Use the Node version documented by the repo. Install Python dependencies with `python -m pip install -r requirements.txt` and frontend dependencies with `npm --prefix web ci`. Use a virtual environment where practical.
3. Run `bash scripts/demo.sh --offline` for a deterministic local demo. For live voice, the same script without `--offline` uses the configured Mistral key. Keep credentials in the environment or local `.env`. The demo launcher enables player actions, or set `GAMBIT_PLAYER_ACTIONS=1` when launching manually. The Vite proxy reads `GAMBIT_BACKEND_URL` or `BACKEND_PORT`.
4. Running alongside an existing preview is fine. Use separate ports and an isolated `GAMBIT_SAVE_DIR` for destructive QA. Treat localhost links from the old chat as session-specific. Use the port the new launcher prints.
5. Regenerate geometry only when editing the authored layout or routing rules. Install Shapely 2.1+ with GEOS 3.12+ in the authoring environment and run `python web/scripts/generate-atlas.py` from the checkout. Review all generated changes together. Shapely is an authoring dependency. The running game consumes checked-in data.

## Files you will need

- **Entry and state** — `web/src/PoliticalMap.tsx` handles camera and city selection. `web/src/App.tsx`, `GameSession.tsx` and `state.ts` wire session state and UI controls.
- **Map art and movement** — `web/src/hud/Cities.tsx` draws the continuous urban fabric and station information. `Terrain.tsx` reads generated biome and river definitions. `Infrastructure.tsx` draws roads, bridges, road traffic, rail, facilities and air patrols. `DecisionMotion.tsx`, `NavalFleets.tsx` and `MapLayers.tsx` are separate paths for events, fleets and markers. Inspect their layer order before adding UI chrome.
- **Data and generation** — `web/scripts/generate-atlas.py` authors the campaign coast, stable province layout, adjacency, ports and rail. `web/scripts/atlas_infrastructure.py` generates biomes, rivers, roads, bridge spans and settlement geometry. Outputs include `web/src/atlas.json` and `data/atlas_adjacency.json`, `data/sea_routes.json`, `data/rail.json` and `data/infrastructure.json`. County and building definitions are in `data/counties.json` and `data/buildings.json`.
- **Engine and contracts** — `contracts/models.py` defines State and the API models. `engine/core.py` owns monthly production, active rail services, movement legality, blockades and construction. `engine/crisis.py` refreshes rail availability on resolution. `engine/saves.py` handles versioned checkpoints and recalculation on restore. `engine/app.py` exposes the API. Use the rail lifecycle as the precedent for additional tracked transport.
- **Regression coverage** — `engine/tests/test_construction.py` covers atlas channels, projects and freight. `engine/tests/test_player_actions.py` covers player diplomacy and fleets. `engine/tests/test_saves.py` covers restoring a crisis. Voice and offline demo regressions are under `voice/tests` and `e2e`.
